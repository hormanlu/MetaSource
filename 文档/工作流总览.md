# AI 创作工作流总览

## 目标

建立一个适合中文长篇小说和 IP 母体创作的可用流程，让 AI 输出尽可能稳定、不跑偏、可复盘。

## 总流程

### 1. 冷启动

1. 冻结 `00-项目总纲/项目简述.md`
2. 冻结 `01-世界观/硬规则.md`
3. 建立 `01-世界观/世界设定.md` 与 `01-世界观/术语表.md`
4. 建立 `02-人物/_模板.md` 与 `04-连续性账本/` 7 份账本骨架

### 2. 规划

1. 补齐 `02-人物/主角/` 与关键配角卡
2. 冻结 `03-剧情/系列主线.md`
3. 在 `03-剧情/方法论/` 下建立骨架视图（七点法 + 雪花法场景清单）
4. 冻结 `03-剧情/卷纲/第一卷.md`

### 3. 写作（单章流水线）

详见 `._agent/编排/单章流水线.md`，八阶段：

1. 任务识别
2. 上下文装配
3. 章纲校准
4. 草稿生成
5. 一致性审校
6. 文风精修
7. 回填账本（7 份逐一检查）
8. 门禁决策

### 4. 审校

对照 `._agent/审计维度.md` 的五维：

- A 一致性（硬）
- B 人物（硬/中）
- C 剧情推进（中）
- D 叙事与文风（软/中）
- E 风险标记（触发升级）

### 5. 回填

7 份账本逐一检查（对照 `._agent/提示词/事实回填.md`）：

- 事实账本
- 时间线
- 伏笔账本
- 人物知识矩阵
- 支线看板
- 情感弧线
- 章节摘要（必填）

同步更新：

- `00-项目总纲/当前焦点.md`
- `._agent/状态/会话日志.md`
- 相关人物卡
- （建议）打 Git tag `snapshot-ch-NNN`

## 默认调用链

- 设定任务：编排中控 → 世界设定师 → 一致性审校员 → 账本维护员
- 人物任务：编排中控 → 角色设计师 → 一致性审校员 → 账本维护员
- 剧情任务：编排中控 → 章纲设计师 → 一致性审校员
- 章节任务：编排中控 → 章纲设计师 → 章节续写师 → 一致性审校员 → 文风精修师 → 账本维护员

## 为什么要加编排层

- 把创作和裁判拆开，避免模型自说自话
- 把最小上下文装配写死，减少无关信息污染
- 把每轮产出都变成可回填、可追踪的工件
- 把"是否通过"从主观感觉，变成显式门禁

## 为什么这样设计目录

- `01-世界观/` / `02-人物/` / `03-剧情/` 负责真相与约束
- `04-连续性账本/` 负责跨章记忆（防失忆）
- `05-正文/` 负责生产与试错
- `06-文风/` 负责风格统一
- `._agent/` 负责 AI 协作机制
- `09-工作区/` 负责非真源的讨论与提案

## 防跑偏机制

- 每次对话都有统一入口文件 `AGENTS.md`
- 每次写章都必须有 `简报.md`
- 每次产出后都要走 `._agent/提示词/审校门禁.md`
- 任何新增正式事实都要回填 7 份账本
- 复杂任务默认走"编排中控"，不让单个技能独占全流程
- 审校发现硬冲突时，禁止直接进入精修
- 用户不选择工作流：系统按 `._agent/意图路由.md` 自动识别意图，并按 `._agent/工作流路由.md` 自动路由
- 改写旧章节前先 checkout 前章快照，防止账本漂移

## 推荐习惯

- 一次只处理一个明确任务
- 没有章纲，不写正文
- 没有回填，不进入下一章
- 不让 AI 同时扮演作者、编辑、裁判三个角色
- 多智能体数量控制在最小必要规模，不为了"高级感"滥加技能
- 写完一章务必执行 `._agent/写完一章.md` 强制清单
