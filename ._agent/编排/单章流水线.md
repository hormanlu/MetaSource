# 单章流水线

本文件定义单章生产的标准多智能体流程。除非作者明确要求跳步，否则章节任务默认按本流程执行。

## 0. 前置条件

进入章节流程前必须满足：

- 已存在 `00-项目总纲/项目简述.md`
- 已存在 `01-世界观/硬规则.md`
- 已存在相关人物卡或至少有人物模板约束
- 已存在卷纲或至少有本章简报
- 已存在章节目录：`简报.md`、`章纲.md`、`草稿.md`

## 1. 阶段一：任务识别

执行者：编排中控

输出：

- 本章任务目标
- 本次允许修改的文件范围
- 需要加载的上下文列表
- 本章通过标准

## 2. 阶段二：上下文装配

执行者：编排中控

参照 `._agent/编排/上下文装配.md` 的"章节写作任务"集合。

## 3. 阶段三：章纲校准

执行者：章纲设计师

目标：

- 检查本章是否有明确目标
- 检查场景链是否成立
- 检查信息释放是否越界
- 检查章末是否有钩子

产出：更新后的 `章纲.md` 或章纲修订建议。

## 4. 阶段四：草稿生成

执行者：章节续写师

目标：

- 按章纲完成草稿
- 不新增未经批准的重要设定
- 用场景和行为体现世界，而不是长篇解释

产出：更新后的 `草稿.md`。

## 5. 阶段五：一致性审校

执行者：一致性审校员

检查项：

- 是否违背 `01-世界观/硬规则.md`
- 是否人物 OOC
- 是否知识越界（对照 `04-连续性账本/人物知识矩阵.md`）
- 是否时间线冲突（对照 `04-连续性账本/时间线.md`）
- 是否遗漏应有回收（对照 `04-连续性账本/伏笔账本.md`）

产出：审校问题清单 + 严重性分级 + 是否可进入精修。

## 6. 阶段六：文风精修

执行者：文风精修师

**进入条件**：只有在阶段五未发现硬冲突时才能进入。

目标：

- 去 AI 味
- 减少解释感
- 增强中文小说现场感
- 保留人物差异

产出：精修稿或精修建议。

## 7. 阶段七：回填账本

执行者：账本维护员

**强制执行，7 份账本逐一检查**：

- `04-连续性账本/事实账本.md`：是否新增正式事实
- `04-连续性账本/时间线.md`：是否新增时间节点
- `04-连续性账本/伏笔账本.md`：是否新增/回收伏笔
- `04-连续性账本/人物知识矩阵.md`：是否有角色知识状态变化
- `04-连续性账本/支线看板.md`：是否推进或结清支线
- `04-连续性账本/情感弧线.md`：是否主要角色情感有显著变化
- `04-连续性账本/章节摘要.md`：新增本章 2-5 行摘要（**必填**）

产出：逐账本的回填建议或直接更新。

同时更新：

- `00-项目总纲/当前焦点.md`
- `._agent/状态/会话日志.md`

## 8. 阶段八：门禁决策

执行者：编排中控

### 门禁分级

- `pass`：可进入下一章准备
- `polish`：只需文风 / 节奏层面的小修，不得动结构与事实
- `revise`：需要回退修章纲或关键场景，必须重走审校
- `rewrite`：结构性失败或硬冲突过多，建议重写本章

必须给出分级 + 触发原因。

## 9. 回填完成条件（强制）

本章只有在以下条件全部满足时，才算"完成"：

- 门禁结果为 `pass` 或 `polish` 且已执行必要精修
- 账本维护员已在 `04-连续性账本/` 完成 7 份账本检查并回填必要条目
- `04-连续性账本/章节摘要.md` 有本章摘要
- `._agent/状态/会话日志.md` 有本章记录
- **建议**：打 Git tag `snapshot-ch-NNN`（支持未来安全 rewrite）

## 失败短路规则

- 章纲不成立：停止后续阶段，先修章纲
- 审校发现硬冲突：禁止进入精修
- 精修只修表达，不能拿来补结构
- 未回填正式事实：默认不视为本章完全完成

## 关联

- 完成后务必参照 `._agent/写完一章.md` 执行最终核对
