# 仓库结构说明

## 设计原则

- `canon/` 只放正式真源，不放临时灵感。
- `manuscript/` 只放正文生产工件（按卷/章组织），可反复迭代但不等于真源。
- `voice/` 单独管理文风，避免文风规则混进设定。
- `ops/` 单独管理工作流、路由、技能、状态与审校体系，避免每次对话从零开始。
- `work/` 用于讨论、灵感、材料、复盘与提案，后续可被提炼进 `canon/`。

## 目录职责

### `canon/00_project`
- 放项目级目标、创作边界、资产化方向。

### `canon/01_world`
- 放世界硬规则和世界观说明书。
- `rules.md` 比 `world-bible.md` 更硬，优先级更高。

### `canon/02_characters`
- 放正式角色卡。
- 角色一旦进入正文，就必须在这里登记。

### `canon/03_plot`
- 放系列主线、卷纲、章纲母模板。
- 用于保证剧情推进不是一次次临场发挥。

### `canon/04_continuity`
- 放时间线、事实账本、伏笔账本。
- 这是防止 AI 长文失忆的关键层。

### `manuscript/`
- 正文生产区，每章一个目录。
- 至少包含 `brief.md`、`outline.md`、`draft.md`，可追加 `review.md` 与 `revise-log.md`。

### `voice/`
- 放 prose style 和 anti-AI style。
- 只描述“怎么写”，不描述“写什么”。

### `ops/prompts/`
- 放会话启动、章节前置简报、审校门禁等可复用提示模板。

### `ops/skills/`
- 放角色化技能定义，让不同任务分工更清晰。

### `ops/orchestration/`
- 放 `v2` 多智能体编排层。
- `orchestrator.md` 定义中控职责与门禁。
- `agent-manifest.md` 定义 agent 角色、输入依赖和写入权限。
- `context-assembly.md` 定义不同任务的最小上下文读取集合。
- `chapter-pipeline.md` 定义单章生产流水线。

### `ops/state/`
- 放当前焦点和最近会话摘要，用于压缩上下文。

### `ops/workflows/`
- 放“内部工作流 SOP”（意图识别、章节生产、审校、提案合并等），用户不必关心，但系统必须遵循。

### `ops/routing/`
- 放意图识别与自动路由规则（自然语言输入 -> workflow）。

### `ops/qa/`
- 放审校量表、门禁阈值与审计维度库，供工作流引用。

### `work/`
- 放讨论会话、零散灵感、资料摘录、复盘评审、合并提案与试验文本。

### `sources/`
- 记录外部开源项目的来源、许可、可借鉴点、冲突点和迁移方案。

## 使用约定

- 灵感先落临时文件，确认后再并入 `canon/`。
- 正文里新增的正式事实必须回填账本。
- 不要把章纲直接写进人物卡或世界观文件。
- 不要把人物小传写进世界硬规则。
- 复杂任务优先让 `Orchestrator` 调度，不直接让单个 agent 读取全仓库。
