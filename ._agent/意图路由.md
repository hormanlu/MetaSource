# 意图识别分类

本文件定义"用户自然语言 → 内部意图 → 工作流"的分类体系。**用户不需要选择工作流，系统必须自动路由。**

## 1. 意图分类（一级）

- `write.chapter`：写 / 续写 / 补写章节正文
- `plan.chapter`：写章简报 / 章纲 / 场景拆解
- `review.chapter`：审校章节（一致性 / 节奏 / 去 AI 味）
- `revise.chapter`：按审校意见修订
- `design.world`：世界观 / 规则 / 术语设计或修订
- `design.character`：人物卡 / 关系 / 知识边界设计或修订
- `design.plot`：主线 / 卷纲 / 伏笔 / 冲突链设计或修订
- `record.idea`：零散灵感收集（进 `09-工作区/灵感/`）
- `record.research`：资料摘录 / 参考（进 `08-调研素材/资料/`）
- `critique.asset`：评估已完成内容（进 `09-工作区/评审/`）
- `propose.canon`：把讨论 / 灵感 / 草稿转成"可并入真源"的提案（进 `09-工作区/提案/`）
- `merge.canon`：把提案合并进 `01-世界观/` / `02-人物/` / `03-剧情/`（需要门禁）

## 2. 触发信号（启发式）

系统按以下优先级做判断（越上越优先）：

1. 用户显式说"写第 X 章 / 续写 / 帮我写一段正文" → `write.chapter`
2. 用户说"章纲 / 大纲 / 场景拆分 / 怎么推进" → `plan.chapter` 或 `design.plot`
3. 用户说"审校 / 点评 / 指出问题 / 有没有漏洞 / 去 AI 味" → `review.chapter` 或 `critique.asset`
4. 用户说"补设定 / 设定矛盾 / 规则怎么定" → `design.world`
5. 用户说"人物设定 / 角色弧 / 人物关系 / 是否 OOC" → `design.character`
6. 用户说"我有个灵感 / 随手记一下" → `record.idea`
7. 用户贴资料 / 链接 / 科普内容 → `record.research`
8. 用户说"把这些整理成真源 / 写进设定 / 落地到真源" → `propose.canon` 或 `merge.canon`

## 2.1 自动升级：真源变更意图

即使用户没有显式说“改设定”，只要意图会落到以下目录，就自动升级为“真源变更任务”：

- `01-世界观/**`
- `02-人物/**`
- `03-剧情/**`

常见自然语言信号：

- “温启山这里我想改一下”
- “这个人物后面不这样走了”
- “他能力不是这个方向”
- “这一段设定不对”
- “把这里统一一下”
- “后面所有相关地方一起调”

一旦命中，系统必须自动附加：

- 读取 `._agent/状态/待同步变更.md`
- 执行 `._agent/编排/变更影响分析.md`
- 输出受影响文件清单
- 同步修改或登记待同步项

## 3. 最少追问策略（关键）

除非出现以下情况，否则不要追问，直接执行：

- 用户请求会导致修改 `01-世界观/` 或 `02-人物/` 的硬真源
- 用户请求"写第 X 章"但仓库里不存在对应章节目录
- 用户请求"审校这章"但未给出章节路径/文件

追问最多 1 个问题，并给出默认建议。

## 4. 工作流映射

意图到工作流文件的映射由 `._agent/工作流路由.md` 统一维护。
