# 写完一章

每写完一章，**必须**逐项完成以下操作。缺一不可。

## 1. 门禁结果确认

- [ ] 编排中控已给出 `pass` / `polish` / `revise` / `rewrite` 其中之一
- [ ] 如果是 `revise` 或 `rewrite`，本清单不适用；回到单章流水线的对应阶段

## 2. 回填 7 份账本

逐一检查 `04-连续性账本/` 下 7 份真相文件：

- [ ] `事实账本.md` — 新事实已登记 / 或确认无新增
- [ ] `时间线.md` — 新事件已登记 / 或确认无新增
- [ ] `伏笔账本.md` — 新伏笔 / 已回收 / 作废 已登记
- [ ] `人物知识矩阵.md` — 新增变化行（如有角色知识变化）
- [ ] `支线看板.md` — 推进 / 结清 / 作废 已登记
- [ ] `情感弧线.md` — 主要角色情感变化已登记
- [ ] `章节摘要.md` — **本章摘要必填**（2-5 行）

## 3. 同步更新

- [ ] `00-项目总纲/当前焦点.md` — 反映新的当前阶段
- [ ] `._agent/状态/会话日志.md` — 新增一行
- [ ] 相关人物卡 — "当前状态 / 最近一次关键行动 / 最近一次知识更新"字段

## 4. 打快照（强烈建议）

```bash
git tag snapshot-ch-NNN
```

**为什么要打快照**：

- 支持未来"只改写第 N 章"的场景：先 `git checkout snapshot-ch-NNN` 让账本回到该章完成时的状态，再改写，避免后续章节的账本状态污染改写。
- 这是 InkOS 血泪经验（issue #34）：没有快照就改写，必然导致账本漂移。

## 5. 章节正文 frontmatter 更新

- [ ] `05-正文/第N卷/第NNN章/草稿.md` 的 frontmatter 状态更新为 `final`
- [ ] `字数` / `场景数` 字段更新

## 6. 进入下一章的准备

- [ ] 在 `05-正文/第N卷/` 下新建 `第(NNN+1)章/` 目录及三件套
- [ ] 在 `03-剧情/方法论/雪花法-场景清单.md` 中登记下一章场景

## 失败条件

以下任一项未满足，本章**不视为完成**：

- 7 份账本检查未全部完成
- 章节摘要未填写
- 会话日志未更新

## 改写已完成章节时的特别规则

**必读**：改写第 N 章时必须执行：

1. `git checkout snapshot-ch-(N-1)` 查看前一章结尾时的账本状态
2. 把账本临时回滚到该快照
3. 完成改写与新审校
4. 重新回填 7 份账本
5. 打新的 `snapshot-ch-N-v2` 标签（不覆盖旧标签）

否则旧章节改写会被后续章节状态污染。
