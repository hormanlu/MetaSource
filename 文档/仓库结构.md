# 仓库结构说明

## 设计原则

- `01-世界观/` / `02-人物/` / `03-剧情/` 只放正式真源，不放临时灵感
- `04-连续性账本/` 是防 AI 长文失忆的 7 份账本，每章必须回填
- `05-正文/` 只放正文生产工件（按卷/章组织），可反复迭代但不等于真源
- `06-文风/` 单独管理文风，避免文风规则混进设定
- `._agent/` 单独管理 AI 编排层，与给人读的真源分离
- `09-工作区/` 用于讨论、灵感、材料、复盘与提案，后续可被提炼进真源
- `09-工作区/归档/` 是软删除仓，永远不用 `git rm` 删除创作产物

## 目录职责

### 00-项目总纲

- 项目级目标、创作边界、资产化方向
- 当前焦点（最常变动）
- 创作路线图

### 01-世界观

- `硬规则.md`：最高优先级真源
- `世界设定.md`：世界观说明书
- `术语表.md`：标准名 + 别名 + 含义，冲突时优先
- `地点/` / `派系/` / `科技与机制/`：一项一卡

### 02-人物

- 一人一卡，文件名即标准名
- 按 `主角/` / `配角/` / `反派与组织人员/` 分类
- 角色卡模板带 frontmatter（类型 / 阵营 / 生态位 / 别名 / 状态 / 标签）
- 角色一旦进入正文，就必须在这里登记

### 03-剧情

- `系列主线.md`：作者的真实规划（真源）
- `卷纲/`：每卷一份（真源）
- `方法论/`：七点法 / 雪花法 / 救猫咪 / 故事网格（工作视图，不是真源）

### 04-连续性账本

7 份真相文件，借自 InkOS 经验：

1. 事实账本 — 已成立的硬事实
2. 时间线 — 事件先后
3. 伏笔账本 — 待回收伏笔
4. 人物知识矩阵 — 谁在什么时候知道什么（**防止"角色突然全知"**）
5. 支线看板 — 未完结支线状态
6. 情感弧线 — 主要角色情感变化
7. 章节摘要 — 每章 2-5 行（**AI 续写的核心上下文**）

### 05-正文

- 每章一目录：`第NNN章/`（三位数字前缀留扩展位）
- 每章三件套：`简报.md`、`章纲.md`、`草稿.md`
- 可追加 `审校.md`、`精修.md`、`修订日志.md`
- `_第NNN章/` 下划线前缀表示实验章，默认跳过构建

### 06-文风

- `散文风格.md`：怎么写
- `去AI味.md`：避免什么

### 07-衍生内容

- 预留占位目录，主线稳定前不填充

### 08-调研素材

- `开源参考.md`：本仓库参考的外部项目与采纳点
- `资料/`：外部资料归档

### 09-工作区

- `灵感/`：零散灵感
- `提案/`：结构化修改建议（合并到真源的唯一路径）
- `评审/`：对已完成内容的批评与复盘
- `归档/`：软删除仓（替代 `git rm`）

### ._agent/

AI 编排层，隐藏目录：

- `意图路由.md` — 12 类意图的触发信号
- `工作流路由.md` — 意图 → 最小调用链映射
- `编排/`：中控、智能体清单、上下文装配、单章流水线
- `技能/`：8 份技能定义
- `提示词/`：会话启动、章节简报、审校门禁、事实回填
- `审计维度.md`：审校五维
- `状态/会话日志.md`：会话记忆压缩
- `写完一章.md`：强制检查清单
- `规则/`：Trae IDE 规则入口

## 使用约定

- 灵感先落 `09-工作区/灵感/`，确认后再经 `09-工作区/提案/` 并入真源
- 正文里新增的正式事实必须回填 7 份账本
- 不要把章纲直接写进人物卡或世界观文件
- 不要把人物小传写进世界硬规则
- 复杂任务优先让"编排中控"调度，不直接让单个技能读取全仓库
- 改写已完成章节前，先 `git checkout snapshot-ch-NNN` 确认账本快照

## 命名约定

- **优先中文**，仅工具强制项保留英文（`AGENTS.md`、`README.md`、`.trae/`、`.gitignore` 等）
- 章节目录三位数字前缀：`第001章/` 而非 `第1章/`
- 实验章：`_第NNN章/`（下划线前缀）
- 文件名即实体标准名：`林默.md`、`旧城地下层.md`（不加前缀编号）
- 别名统一走 frontmatter `别名` 字段
